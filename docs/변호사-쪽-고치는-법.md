## 고치는 순서

**1.** `main.js` 를 엽니다. `const attorneys = [` 를 찾습니다.

**2.** 고치실 분의 묶음을 고칩니다.

```js
{
  name: "김제도", role: "변호사",
  field: "의료사고 · 형사 · 민사",      ← 이름 바로 아래 작은 줄
  quote: "…",                          ← 그 아래 큰 글씨 한 줄
  intro: "…",                          ← 사진 옆 소개글
  edu:      [ … ],                     ← 학력
  work:     [ … ],                     ← 경력
  books:    [ … ],                     ← 저서
  cases:    [ … ],                     ← 주요 업무사례 (카드)
  wins:     [ … ],                     ← 성공사례 (카드)
  advisory: [ … ]                      ← 자문
}
```

**3.** 홈페이지 폴더에서 아래 한 줄을 칩니다.

```
node tools/make-lawyer-pages.mjs
```

네 장이 다시 만들어집니다. 제목과 설명이 한도를 넘지 않았는지도
함께 재 줍니다.

**4.** 올립니다.

---

## 어느 묶음이 어디에 나오나

| 묶음 | 쪽에서 | 대문 명단에서 |
|---|---|---|
| `edu` 학력 | **약력**의 첫째 칸 | 카드 줄 |
| `work` 경력 | **약력**의 둘째 칸 | 카드 줄 |
| `books` 저서 | 약력의 경력 칸 안에 | 카드 줄 |
| `advisory` 자문 | **약력**의 셋째 칸 | 카드 줄 |
| `cases` 주요 업무사례 | **주요 업무사례** (카드) | 카드 줄 |
| `wins` 성공사례 | **성공사례** (카드) | 안 나옴 |

> **2026-10-29.** 학력 · 경력 · 자문을 **「약력」 한 묶음**으로 합쳤습니다.
> 넓은 화면에서 세 칸으로 나란히 섭니다.
> 그 전에 있던 **「맡는 일」 묶음은 뺐습니다.** 분야가 이름 바로
> 아래에 이미 적혀 있어 같은 말을 두 번 하고 있었습니다.

**비어 있는 묶음은 그 자리가 아예 나오지 않습니다.**
예를 들어 지금은 `wins` 가 네 분 모두 비어 있어서,
어느 쪽에도 「성공사례」 칸이 없습니다.

> 대문 명단 카드에 보이는 줄은 위 묶음을 차례로 이어 붙여
> **저절로** 만들어집니다. 따로 적으실 것이 없습니다.

## 주요 업무사례 · 성공사례

**주요 업무사례**(`cases`)는 **어떤 사건을 다루었는가**입니다.
결과를 적지 않습니다. 묶음마다 카드 한 장이 나옵니다.

```js
cases: [
  { label: "의료 · 문서", items: ["의료법위반", "업무상과실치사상"] }
]
```

**성공사례**(`wins`)는 **결과**입니다.
결과가 까만 알약으로 카드 맨 위에 먼저 나옵니다.

> ⚠️ **넣으시기 전에 `docs/승소사례-적는-법.md` 를 읽어 주십시오.**
> 광고규정에 선이 있습니다. 승소율 · 건수 · 단정 표현은 쓸 수 없고,
> 잘못 적으면 징계 대상입니다.

## 사진을 바꾸실 때

`image` 에 적힌 파일을 `assets/` 에 같은 이름으로 덮어쓰시면 됩니다.

| | |
|---|---|
| 크기 | 세로로 긴 것. **가로 1000px 이상** (지금 넉 장은 1024 × 1280) |
| 모양 | **상반신**. 네 분이 같은 크기로 보여야 합니다 |
| 바탕 | 밝은 단색 |

⚠️ **전신 사진을 넣지 마십시오.** 한 분만 전신이면 네 분이
제각각으로 보입니다. 대표님 전신 컷(`lawyer-01-v2.webp`)은
대문 인사말 자리에만 씁니다.

⚠️ **넉 장을 같은 비율로 맞춰 주십시오**(2026-10-29).

지금은 **1024 × 1280**, 가로가 세로의 **0.8배**입니다.
쪽의 사진 칸을 그 비율에 맞춰 놓았기 때문에
**사진이 한 점도 잘리지 않습니다.**

비율이 다른 사진을 넣으시면 잘립니다.
꼭 다른 비율로 쓰셔야 하면 `style.css` 의 `.lw-hero` 에 있는
**`calc(var(--lw-h) * 0.8)`** 의 `0.8` 을 (가로 ÷ 세로)로 고치십시오.
주석에 적어 두었습니다.

⚠️ **팔이 보이게 찍힌 것**을 쓰십시오.
2026-10-29 에 정호길 대표변호사만 팔이 보이고 나머지 세 분은
팔이 잘린 일이 있었습니다. 대표님 사진만 인물이 크게 찍혀
팔이 높이 있었기 때문입니다.

## ⚠️ style.css 나 main.js 를 고쳐 올리셨다면

브라우저는 꾸밈 파일(`style.css`)을 한 번 받아 두고 한동안 다시
받지 않습니다. 그래서 **글은 새것인데 꾸밈은 옛것**인 상태가
생깁니다. 2026-10-29 에 실제로 그랬습니다.

올리시기 전에 **한 줄 더** 치십시오.

```
node tools/bump-assets.mjs
node tools/make-lawyer-pages.mjs
```

주소 뒤에 `?v=20261029` 같은 날짜표가 붙습니다.
브라우저가 다른 파일로 보고 새로 받아 갑니다.

**글만 고치셨을 때는 돌릴 필요가 없습니다.**

## 제목 · 설명 · 검색어를 바꾸실 때

이것만은 `main.js` 가 아니라
**`tools/make-lawyer-pages.mjs` 의 `META`** 에 있습니다.
자료가 아니라 「문구」라서 따로 두었습니다.

바꾸신 뒤 같은 명령을 다시 치시면 됩니다.
**제목 60칸 · 설명 155칸 · 검색어 20개**를 넘기면 화면에
경고가 뜹니다.

## 새 변호사를 더하실 때

1. `main.js` 의 `attorneys` 에 묶음을 하나 더합니다.
   `slug` 와 `page` 를 꼭 적으십시오. 없으면 쪽이 안 만들어집니다.
2. `tools/make-lawyer-pages.mjs` 의 `META` 에 같은 `slug` 로
   제목 · 설명 · 검색어 · 맡는 일을 적습니다.
3. 명령을 칩니다.
4. **`sitemap.xml` 에 그 쪽을 더합니다.** 이건 아직 손으로 합니다.

알려 주시면 제가 해 드리겠습니다.
